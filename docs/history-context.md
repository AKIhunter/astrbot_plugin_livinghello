# 旧情绪与历史搜索输入

LivingHello 在发送给 Provider 的副本中移除可识别的旧情绪，缩短更旧的百度搜索结果。请求历史和运行器原消息保持原样，不批量改数据库。新状态通过宿主 `mark_as_temp()` 参与本轮调用，保存时排除。

## 情绪

LivingEmotion 的 `Application.on_llm_request()` 只对 `<!--livingemotion:state:v1-->` 状态块标记临时属性，构造文字与原逻辑相同。记忆、补看记录及情绪经历不受影响。

Hello 的 `_freeze_emotion_snapshot()` 保留同一事件首次获得的完整状态，最终装配后建立 `HistoryView`。旧状态必须是历史 user 消息中首块正文之后的独立 text 块，且具有完整固定说明头；用户正文里的引用、混合字符串、未知格式均保留。

发送时复制需要处理的消息，保留媒体、角色、工具关联与宿主 checkpoint。当前临时块始终保留。宿主参数补查使用 `model_dump()` 时会丢掉临时属性，因此绑定运行器时额外记录本轮用户消息指纹；相同内容的旧消息也保守保留。

## 搜索

候选在最终装配时冻结，不随工具循环中追加的内部 user 指令重新计算。只有以用户消息开始、工具调用与结果完整配对、最后有机器人正文的轮次才算完成。

固定策略：

| 条件 | 行为 |
| --- | --- |
| 当前轮、最近两轮完整对话 | 保留全文 |
| 更旧的 `web_search_baidu` 结果 | 原文至少 2000 字符，且摘录更短时精简 |
| 每条 snippet | 最多 160 字符，优先停在句子边界 |
| 标题、完整 URL、引用 index、来源顺序 | 全部原样保留 |
| 未知字段、坏 JSON、空结果、失败、调用 ID 不唯一 | 保留全文 |
| 无法挂载补读工具、开启黑名单的群聊、Provider 不支持工具 | 保留搜索全文 |

精简版本明确标记 `search_snippets_only`，不声称网页已核实。发布日期和获取时间为 `null`，不会用当前时间伪造历史时间。

`livinghello_read_search_result(tool_call_id)` 返回本轮授权候选中的完整原结果。参数 schema 显式声明必填 ID，不接受会话或用户参数。原文来自已加载历史，不搜索、不读数据库、不调用外部模型；同一 ID 只读一次，之后提示复用本轮工具结果。补读全文会增加下一次模型输入长度。

工具绑定到复制的 `ToolSet`。每次补读重新核对 event、origin、会话、发件人、人格和策略 revision。任务正常结束、取消、异常、插件卸载时清空范围并恢复运行器方法。

## 发送边界与限制

`attach_reply_contract()` 最终图片处理后调用 `prepare()`；`trace_agent_begin()` 用现有调用栈定位方法找到当前运行器。`HistoryView.bind()` 仅包装该实例的 `_sanitize_contexts_for_provider()`，覆盖普通、流式、宿主后备及参数补查调用，不更改运行器类或 Provider。

单独的 `ReasoningRetry` 直接应用相同副本规则。优化独立于回复兜底开关。宿主接口不兼容或投影异常时跳过优化，保留原输入并记录原因。

宿主自动压缩发生在该发送边界之前，计数与压缩输入仍可能含旧情绪和搜索全文；已经融入摘要的旧情绪不能靠块标记清除。宿主自行淘汰原搜索轮次后也不保证可补读。此次不调整压缩配置或算法。
