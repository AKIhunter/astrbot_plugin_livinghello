# 图片、OCR与技术正文的资源边界

适用仓库版本 **2.9.1**。以下限制保护图片解压、OCR拼接、正文扫描与代码缩进；
自动生效，不需要新增配置。

## 实际规则

| 路径 | 限制 | 达到限制后的行为 |
| --- | --- | --- |
| 图片源尺寸 | 长边≤32768，像素≤64×1024×1024 | 解码前拒绝 |
| 实际解码 | JPEG draft后≤4×1024×1024像素；PNG/GIF按源像素检查 | 省略图片，不回退原图 |
| 图片并发 | 进程内最多两份实际解码，无准入等待队列 | 第三份立即省略；取消await后线程仍持有槽位 |
| HTTP下载 | 8秒总时限，8MiB字节上限 | 保留已取得OCR，画面标为未读 |
| OCR | 最多300行，6000字正文，置信度≥0.75 | 先截取再拼接，追加截断说明 |
| 图片证据汇总 | 24000字 | 追加未收录说明 |
| 正文识别 | ≤16384字，JSON累计尾部扫描≤32768字、≤16次 | 保留整份原文，不继续清理 |

MiB=1048576字节；像素限制与文件字节限制不能互相替代。JPEG可先draft降采样，
不支持draft的PNG/GIF先检查原尺寸。该预算不覆盖宿主、其他插件或上游自行处理的图片。
缺少Pillow时内联图片省略；正常HTTP和本地路径的原有预算规则仍保留。

平台支持时刷新一次图片链接，OCR与下载并行。少字、数字、UI标签等OCR结果仍调用视觉模型，
文字不能冒充完整画面；无法下载时不发起视觉调用，不执行图片内的指令。
视觉每批两张、保持原消息编号，最多六次调用；每次总尝试数仍为1。

## 开关与兼容

在 `guard` 控制台的回复设置开启回复方式管理与“标点清理”后，聊天标点换成间隔；
代码围栏、行内代码、常见命令、网址、邮箱、路径、数字格式与表格保留。
关闭清标点后按原标点发送。超长或识别预算耗尽时，禁忌词清理也保留整份原文。

工具入口仅处理 `send_message_to_user` 的 `plain` 正文，附件名称、路径、URL、会话参数保持原值。
分段先使用原标点，再清理每段；原生分段开关仍控制是否多条发送。模型建议段长8–20字，
短答不凑字数，答案总字数不受限制，代码和表格不为段长强拆。

插件仓库不包含宿主修改。宿主重复下载的绕过与超时修复须另行核对宿主版本；
安装本插件不能证明那条宿主链路已经修复。

## 离线验收

运行仓库入口：

```bash
python -B run_offline_tests.py
```

图片测试需要Pillow；真实原生装饰和发送测试显式设置 `ASTRBOT_NATIVE_SOURCE`，
其目录内须含 `core/`，并安装宿主回放依赖。没有依赖时跳过对应用例，跳过不算通过。
新增回归在 `tests/test_boundary_safety.py`：覆盖像素边界、JPEG draft、并发与取消、
OCR分配与长度、JSON预算、长单词延迟、技术内容、实际工具钩子及分段组合。
平台、模型、下载使用替身，真实付费API调用为0次。公开版全量基线与候选按同环境失败名称比较，
生产快照的测试数量不替代本仓库验收。

历史基线、反向回放和失败对照统一见[更新日志原始来源](../CHANGELOG.md)；
当前测试数量以本提交检查结果为准，缺依赖跳过不计通过。
