# 独立输入、人设隔离与断线补答

适用LivingHello 2.9.1。无需第三方感知、人格或补答插件；仍使用AstrBot原生主模型、
人格、会话、Agent工具循环、分段和平台发送。

## 输入与人格

`input/guard_understanding.py`独立展开转发、引用、卡片及媒体，按本插件开关、
来源预算和去重标记执行。引用作者、当前正文和视觉摘要同时保留；关闭图片理解仍能处理文字。

`integrations/guard_identity.py`从原生配置、最终人格、人格正文、会话ID和发送者生成指纹；
历史补读额外绑定本轮系统提示。工具证据与搜索历史补读只在指纹一致时复用；同ID改人格正文、切原生配置、
切会话、换发送者或名单变化均使旧资料失效。缺少可信配置时不开放补读。
人格沿用现有规则：原生配置页固定的人格优先于会话旧人格；未固定时由宿主解析会话人格。

## 故障恢复

开启「断线恢复」后，文字判定故障由现有状态机登记并探测。
`gate/guard_recovery_replay.py`在内存保留每个受影响会话最新原消息，最多256个会话：

1. 判定依赖恢复后，读取同一冻结故障窗口。
2. 缺少原消息标为`unavailable`；关闭、撤回、名单拒绝或过期标为`no_reply`。
3. 尚有效的消息创建独立事件副本，重新读取原生会话与人格并执行LH参与判定。
4. 只运行AstrBot Agent、结果装饰与发送阶段，不重放普通插件命令和消息监听。
5. 正式正文有发送回执才记`completed`；仅生成而未发送不能算成功。
6. 未产生副作用的故障沿用600秒重试冷却；发送或工具执行结果未知记`send_unknown`，
   不盲目重放。并发恢复受同一故障锁保护。

宿主发送的模型错误提示也属于发送副作用，但不是正式补答，不能据此记`completed`。
补答单会话执行最多180秒，保留原消息起点，等待恢复不能重置有效期。
默认回复有效期300秒短于600秒冷却，所以默认场景通常只恢复正常判定，
过期旧消息静默收尾；不承诺每条断线期间的消息都补答。

原消息不落盘。重载后持久故障记录仍可读取，但缺少内存原消息的会话准确标为
`unavailable`，不从会话ID猜测正文。已有未知发送状态仍保留，不能通过重载触发重复发送。
卸载清空内存并取消本插件恢复任务。

## 接口与迁移

显式恢复回调使用`livinghello.classifier-recovery.v1`，包含故障`event_id`及会话`status`。
本插件不再自动发现外部恢复实现。旧外部事件键和私有文本块不参与LH决策，
历史日志与数据库保留；当前页面仅展示LH结构化流水，其他背景原块保留为资料。

LE准备耗时只读取本事件的`livingemotion:wake_prepare_seconds`，由
`integrate_livingemotion_catchup`控制是否从有效期扣除。无有效计时不延长期限。
LE、Memory可选公开契约保持各自职责，名单不是其他插件的全局历史过滤器。

运行`python -B run_offline_tests.py`验证输入、人格、恢复、未知副作用和移除依赖检查。
真实宿主验证须额外使用隔离宿主与假Provider、假平台发送；离线通过不代表生产已更新。
