# 配置参考

面向使用者与维护者：查参数、默认值及保存范围。插件默认值以 [_conf_schema.json](../_conf_schema.json) 为唯一来源；原生字段来自 [integrations/guard_native_settings.py](../integrations/guard_native_settings.py)、[reply/guard_native_reply.py](../reply/guard_native_reply.py)，独立生图默认值来自 [images/guard_image_settings.py](../images/guard_image_settings.py) 的 `DEFAULTS`。已核对源码：2026-11-13；字段变化时同步更新并运行校验。

主模型失败后的重试、管理员提醒和停止条件见[主模型失败兜底](reply_fallback.md)。该开关默认关闭，与文字判定断线恢复独立。

## 配置保存在哪里

| 配置域 | 权威保存位置 | 生效范围 |
| --- | --- | --- |
| LivingHello 参数 | AstrBot 保存的本插件配置 | 本插件；已保存值优先于下表默认值 |
| 原生模型、人格、语音、排版、分段 | 所选 AstrBot 原生配置 | 实际分配到该配置的会话 |
| 固定人格 | 所选原生配置 agent_runner.config.persona.persona_id | 覆盖会话旧人格；旧 native_persona_pins.json 不再读取 |
| 独立AI生图 | 本插件 image_generation.json | 全插件能力，复用所选模型连接 |

统一保存栏逐域返回结果，失败草稿保留。后端检查字段白名单、类型、范围和读取版本，共享保存锁，合并最新磁盘字段并刷新对应原生流水线。保存失败恢复本次触及字段及人格固定，不持久化运行时临时唤醒词或动态路由配置。选择原生配置只改变编辑目标；不替代 AstrBot 的会话分配。

### 逐项设置与用法

每项同时可在AstrBot插件配置页按字段名设置。表中位置是LH控制台入口；
已有保存值优先于默认值。数值范围由页面、保存校验与运行时共同约束，
互相关联的时限另见下文。提示词字段可在“预置提示词”编辑并恢复预置。

| 配置项 | 控制台位置 / 作用与例子 |

### 时限与预算如何配合

`gate_context_max_age_seconds=0` 表示不做时间筛选，按判定流水条数取近期消息；正数只允许30–3600秒。机器人上一句、引用和近期图片遵循相同时间开关，近期图片仍对齐已选流水条目。现有会话隔离、内存条数与字符上限保留；不会恢复重载前历史，也不关闭 `gate_reply_max_age_seconds`。

总判定预算与视觉共享预算按调用次数计数，包含复判及兜底。例如文字一次、看图一次、主模型兜底一次，会消耗 3 次总预算和 2 次视觉共享预算。设置 `0` 只关闭该项限制。

文字/视觉时限约束单层，整条判定时限含记忆检索；碎片等待和主回复不属于该判定总时限。自主回复机会有效期从收消息到发送计时，配套开启时仅扣除当前事件有效的配套插件准备耗时。模拟打字等待另行处理，新消息与已触发取消仍有效。

碎片等待还有一层批次总上限：`fragment_max_wait_seconds` 从该批第一条消息起算，默认 10 秒，`0` 不限制；续发只重置 `fragment_wait_seconds` 的静默计时，不延长总上限。回复有效期小于「静默等待 + 总上限 + 40 秒」时，控制台会在保存栏提示整批回复可能在发送前过期；只提示，不阻止保存。

群消息主动判定由 `proactive_group_judge` 控制：`whitelist_empty`（默认）在群白名单为空时，让没有 @、没有称呼唤醒的普通群消息也补一次判定；`all` 不依赖白名单是否为空（白名单内的群也补判定，名单外群仍按既有规则只读静默）；`off` 不补，完全沿用宿主主动回复策略。灰名单仍要求显式呼叫，黑名单不进入判定，机器人自己的消息和插件推送的消息不触发；同一批次只补一次，命中主动回复冷却时跳过，已有在途回复仅作为谨慎接话的背景。通过预筛的普通群消息可能调用判定模型，成本随消息量上升；判定为静默时不会进入主模型生成。私聊行为不受此项影响。

LivingMemory / LivingEmotion 接入开关均默认关闭，安装插件不等于生效。设置位置为 AstrBot 管理面板 → 插件 → LivingHello → 配置。开启后还需配套插件已激活、范围与引擎就绪；Memory 关闭只移除召回注入与召回工具，原生归档和长期写入工具仍保留。详见 [四种接入组合](integrations-and-flow.md)。

水位规则由 `watermark_scope` + `private_watermark_window_seconds` 共同控制。窗口从消息到达时刻（不是生成开始）起算：窗口内同一会话又来新消息时，尚未发送的旧回复被顶替——丢弃正文、停止剩余分段气泡，已发出的不回收；窗口外旧回复照发。`watermark_scope=private`（默认）只作用于私聊，群聊保持原有发送前复核行为；设为 `all` 时该窗口同时用于群聊。`private_watermark_window_seconds=0` 表示关闭水位顶替，旧回复一律发送。300 秒回复机会有效期优先级高于水位，超期一律丢弃。

### 0的含义

| 设置 | 0表示 |
| --- | --- |
| 上下文有效期 gate_context_max_age_seconds | 关闭时间过滤，条数和字符上限保留 |
| 判定流水条数 gate_context_messages | 不提供近期流水 |
| 碎片等待 fragment_wait_seconds | 不等待碎片，也没有该等待批次的撤回窗口 |
| 碎片总上限 fragment_max_wait_seconds | 不限制批次总时长，续发可无限延长整批 |
| 最多分几段 max_segments | 不额外限制文本段数，仍遵守宿主发送限制 |
| 每小时判定预算 gate_hourly_budget / gate_vision_hourly_budget | 关闭对应预算限制 |
| 图片观察缓存 gate_image_cache_ttl_seconds | 关闭观察缓存 |
| 生图每日额度 daily_limit | 禁止生图 |

### 模型选择

判定小模型留空跟随会话当前模型；指定项失效可能回退会话模型，应查看日志。原生视觉候选按已知型号和宿主能力声明筛选；路由上游优先采信 `api_type=image_to_text/multimodal`，锁定上游直连时保留同一声明，`chat` 等类型不进入视觉候选。能力声明不代表上游 API 已经联网实测。判定可使用已注册路由 provider；上游标签的解析由插件及路由提供者约定，主模型回退列表用逐项下拉添加，按列表顺序回退，不允许重复。

`vision_shared_provider_id` 是视觉共用项；`vision_provider_id` 覆盖参与判定，`understand_image_provider_id` 覆盖独立内容理解，两项留空时跟随共用项。原生配置中已移除图片理解桥，旧宿主字段保留但不再由本页编辑。当前事件启用配套插件感知时优先沿用其解析，避免重复独立理解。

### 合并转发与 XML 卡片

在「内容理解」配置 `understand_expand_forward`、`understand_forward_max_depth` 和
`understand_forward_max_nodes`。XML 聊天记录与普通转发共用限制，外层计入深度；
深度为1时，外层内部的下一层转发不会展开。关闭展开开关或达到限制时也不会回拉。
XML 必须有 `m_resid/resid` 才能获取内部正文；缺失 ID 的预览只能作为卡片预览，
不能凭 `m_fileName` 还原正文。详见[修复与边界说明](forward-xml-and-vision.md)。

“AstrBot配置人格”统一显示编辑配置及原生人格，模型、语音和排版使用可展开二级分组；问号解释保存位置与用途。编辑配置保存到插件数据目录的 `native_selected_profile.json`，刷新与插件重载后继续选择同一配置，不依赖 iframe 本地存储。选择配置不会修改人格，也不会替代宿主会话分配；人格仍须手动保存后固定。主模型改变不连带改变判定小模型。此编辑目标是本控制台共用的选择记录。

多 API 路由的具体聊天 Provider 可用于主模型与回退模型，下拉显示路由配置中的 API 名称和模型名，保存稳定的 `provider_id:upstream_N`。旧版 `provider::model` 虚拟项仍仅用于插件内部判定，不写入原生主模型。

人格以原生 `persona_id` 为唯一真源，原生页面修改后立即按该值解析，刷新和重载不会恢复旧固定副本。指定人格被删除时明确报错，需重新选择或保存 `[%None]`；不会静默切换身份。路由编号是否稳定由路由插件决定，增删或排序后应核对所有已保存引用。

语音回复候选只读取 AstrBot 已注册的 TTS Provider，与聊天模型严格分开。`tts_enabled` 和 `tts_provider_id` 双向同步所选原生配置；`trigger_probability`、`dual_output`、`use_file_service` 不由本页编辑。开启语音回复仍需有效 Provider、会话允许且触发概率通过。

独立生图同时读取已激活路由的服务端上游配置，因此 `image_generation` 类型即使没有注册聊天 Provider，也可作为生图连接。`route_enabled` 只控制自动聊天候选链，不影响独立生图选择；路由整体关闭或连接删除后停止使用。密钥和 API 地址只在服务端用于请求，不包含在浏览器列表中。生图模型列表不会包含 embedding、rerank、STT/TTS 等非生图类型。

## AstrBot 原生分段

权威配置为 `platform_settings.segmented_reply`。保留 `enable`、`only_llm_result`、`interval_method`、`interval`、`log_base`、`words_count_threshold`、`split_mode`、`split_words`、`regex` 和 `content_cleanup_rule` 原生字段。

本页“仅对模型结果分段”对应 `only_llm_result` 的模型段落提示，“启用分段回复”对应 `enable` 的多消息发送。细化项 `second_period`、`split_words_enabled`、`max_segments` 编码在原生正则的 `at-guard-reply-v2` 注释中，不另存插件分段配置；默认关闭细化、最大段数 0 不限。旧规则继续兼容，本页保存新控件后进入管理模式。

间隔只由原生管线执行一次；超过 `words_count_threshold` 的原生不分段行为仍保留。第二句号只识别中文 `。`，其他启用分段词立即拆分并重置句号计数。完整示例见[设置分段回复](usage.md#设置分段回复)。

风格提示词固定附加在每次描述之后，用户这轮明确要求画风时以用户描述为准。
启用映射时默认描述建议400字、硬上限500字、描述与时间和风格总长900字，超长描述在扣额度前

- 水彩手绘：`水彩手绘，纸张纹理，颜料自然晕染，边缘柔和，留白充足，不出现文字和水印。`
- 日系胶片：`日系胶片人像，35mm 胶片质感，轻微颗粒，柔和逆光，低饱和，真实皮肤质感。`

## 原生分段逐项用法

位置：“回复与私聊 → 原生配置 → 分段回复”。这些控件读取所选原生配置的当前值，
不另存一份LH默认值；先核对会话实际分配到该配置。保存后只影响该配置的后续回复。

| 原生字段 / 控件 | 作用与例子 |
| --- | --- |
| `enable` | 开启多气泡发送，关闭整段发送；不决定模型是否写多个自然段 |
| `only_llm_result` | 仅管理模型结果的分段，避免非模型消息也进入相同分段规则；实际以宿主管线为准 |
| `interval_method` | 选择固定或算法间隔，例如使用固定间隔时由interval决定等待 |
| `interval` | 固定间隔秒数；每个气泡之间只由原生管线等待一次 |
| `log_base` | 算法间隔的底数；固定间隔模式不使用它 |
| `words_count_threshold` | 超过原生阈值的正文不按分段发送，避免长答案大量刷屏 |
| `split_mode` | 选择原生分段词或正则；切换后核对split_words/regex的实际生效项 |
| `split_words` | 原生分段词；例如中文句号与问号，正文按配置边界拆分 |
| `regex` | 原生分段正则；LH细化配置编码在at-guard-reply-v2注释内 |
| `content_cleanup_rule` | 宿主分段后的文本整理，和LH标点清理分别控制 |
| 第二句号 `second_period` | 开启后第二个中文句号才拆段；其他分段词仍立即拆分并重置计数 |
| 分段词 `split_words_enabled` | 开启细化分段词处理；关闭保留宿主正则与其他独立规则 |
| 最大段数 `max_segments` | 0不限段数；正数控制细化段数，代码与技术正文不强拆 |

原生模型、语音、人格和排版字段在上方“AstrBot原生字段”逐项列出。
streaming_response关闭为非流式；tts_enabled关闭不请求TTS；
t2i关闭保留文字。开启这些能力后分别选择有效模型/排版服务和模板，
它们不会替代参与判断、撤回或发送有效期守卫。

## 请求诊断存储

`request_traces.sqlite3` 与生图额度库分开，自动保存最近600次请求，每次最多96条步骤及64KiB快照；待写队列最多128个请求。超限或数据库不可写时降级采集，不阻断回复；详情会提示截断或不可读。重载有界刷新，历史未完成请求显示结束状态未采集。

追踪只保存ID、受控原因、功能/工具/模型显示名、耗时、次数和发送组件类型，不新增提示词、思考、工具参数或原始响应副本。不新增可编辑配置，原有功能开关及每日额度政策继续生效。[使用方法](usage.md#按请求id排查)。
