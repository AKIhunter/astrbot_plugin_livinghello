# 使用指南

面向插件使用者：完成控制台设置并根据记录排查行为。配置数值以[配置参考](configuration.md)为准，内部执行规则见[流程说明](architecture.md)。已核对仓库源码：2026-11-04；页面或发送行为改变时更新。

## 打开控制台并保存

安装后在 AstrBot 插件详情打开 `guard`。控制台有运行概览、判定设置、回复与私聊、流程与试跑四页；最近判定位于概览。切页保留草稿，键盘方向键、Home、End 可切换，URL 锚点可恢复页签。

在判定设置选成本合适的小模型。日常使用硬闸门 `enforce`；模型留空会跟随会话模型。按需选择视觉模型，确认上游 API 真有图片能力。标题右侧 `?` 显示完整说明和两个示例，顶部参数手册可搜索字段名、用途和示例。

改动后点击底部“保存更新”。普通参数、原生分段、原生模型/人格和独立生图分别返回结果；失败草稿保留。“放弃更改”恢复未保存内容。存在原生草稿时锁定编辑目标；保存成功后页面展示该目标实际值。调整判定口径不会清零统计，清零是独立操作。

大多数设置保存后生效。机器人称呼的运行时唤醒前缀在启动时注册，修改称呼后重载插件。模型、人格、语音或分段保存只修改选中的原生配置，检查测试会话是否由 AstrBot 分配到此配置。

## 固定主模型与人格

在“回复与私聊 → 原生配置 → AstrBot配置人格”核对配置并选择人格，刷新后继续编辑同一配置，再展开模型分组。更换主对话模型会同步保存到 AstrBot；判定小模型仍单独配置。回退模型逐项下拉选择，支持添加、移除与上移，按顺序使用，不允许重复。已注册的路由具体上游按其 API 名称显示，可用于主模型及回退；专用 `image_generation` 上游在 AI 生图分组中选择。

手动选择人格，或点击“固定当前人格”，再保存才激活固定。以后刷新、文字试跑和旧会话选择不自动换人；选择“无人格”同样是明确固定。使用从绫时需其兼容实现优先读取固定人格；固定人格删除后明确报错，应手动换成有效人格并保存。

## 设置语音回复

在“回复与私聊 → 原生配置 → 语音回复”设置 **使用语音回复** 和 **默认 TTS 模型**。两项与主对话模型一样，读取并写回当前选择的 AstrBot 原生配置；在 AstrBot 原生页面修改后，点击“重新读取”即可同步到本页。

开启语音回复不会自动选择 TTS 模型。默认模型可留空，由会话单独选择；若配置和会话都没有有效 TTS Provider，本轮仍保留文字，不会伪造语音成功。TTS 触发概率、同时输出文字、文件服务继续在 AstrBot 原生页面设置。

聊天模型与 TTS 模型按角色隔离：TTS Provider 不会出现在主模型或回退模型中，聊天 Provider 也不能保存为默认 TTS。保存冲突时页面保留草稿，重新读取后再确认。

## 只限制流水条数

在“判定设置”将 **上下文有效期（0不限时间）** 设为 `0`，将 **判定参考的流水条数** 设为需要的数量，再保存。例如设为8条，即使消息间隔超过1小时，也会从当前内存流水中取最近8条；实际条数仍受字符上限影响。

主模型另有“参与回复的上下文条数”，按生成需要单独设置。这个时间开关不读取全部归档、不恢复重载前流水，也不关闭发送时的回复机会有效期。正数有效期允许30–3600秒，先按时间筛选再取条数。[各类0值含义](configuration.md#0的含义)。

## 设置分段回复

在选中的原生配置中设置，使用同一份 AstrBot `platform_settings.segmented_reply`：

| 想得到的效果 | 设置方式 |
| --- | --- |
| 连贯普通回复，一条发送 | 关闭“仅对模型结果分段”和“启用分段回复” |
| 模型自行组织段落，一条发送 | 开启“仅对模型结果分段”，关闭“启用分段回复” |
| 模型段落拆成多条消息 | 两个开关均开启 |
| 模型结果进一步按标点细分 | 开启多消息发送，再按需开启“第二句号”或“分段词” |
| 限制文本段数 | “最多分几段”设为 1–20；0 不限制 |

“第二句号”仅对中文 `。` 计数，每段第一个不拆，第二个拆，分段后重置。“分段词”独立默认关闭；其他已启用分段词立即分段。例如同时启用第二句号并将 `！` 作为分段词，`甲。乙。丙！丁。戊。` 得到 `甲。乙。`、`丙！`、`丁。戊。`。

超过最大段数时合并相邻段并保留全部正文；媒体位置和平台限制仍需遵循宿主。代码围栏内部保留换行与标点，表格保持必要格式。原生“不分段字数阈值”是超过阈值后不拆，不能当作硬切长度。

旧原生分段规则继续兼容，通过本页保存新开关后进入新管理模式。发送间隔不在常用控件中，原生参数仍保留。引用和 @ 是独立确定性开关，只给首条可承载头的正文增加有效原生头，不伪造平台不支持的组件。

## 等待碎片与撤回保护

同一会话、同一用户每次续发重置安静期。例如等待 3 秒，第 0、2、4 秒分别发 @、短句和问题，第 7 秒合并处理，最后一条保留触发资格。其他用户不重置这一批，也不加入用户输入。

私聊等待 `fragment_wait_private` 与私聊参与过滤 `apply_to_private` 独立。只开等待时合并后交给主模型；两者都开才增加评分。群聊 `off` 不聚合，已开启的私聊等待仍可独立工作。

群聊和私聊撤回开关独立。只有在该碎片批次安静期截止前收到有效撤回通知才取消整批未发送回复；取消一经触发持续有效。窗口外新撤回不取消生成或模拟打字中的回复。等待为 0 或私聊未启用等待时，没有这一保护窗口；已发送消息不会被自动删除。

模拟耗时默认关闭。开启后每条实际正文按“非空白字符数 ÷ 速度”等待，只计算一次；等待期间仍检查新消息和已触发取消。

## 查看流程与文字试跑

在“流程与试跑”填写当前消息、机器人上一句和必要上下文，然后使用已保存参数运行。消息最多 800 字，上下文最多 30 条、每条 800 字。点击或用键盘选中节点，查看实际尝试、模型、分数、修正原因、输入与已采集耗时。

试跑会产生判定 API 用量，但不计业务统计和预算；不读取真实用户记忆、不上传图片、不生成主回复、不发送消息。生成图显示计划，硬闸门否决后显示不会生成。没执行或没采集的数据明确标记，不能当作真实成功的工具调用。

## 查看最近判定

概览默认展示最近10条，仅保留判断结果、`request_id` 和详情入口；不重复显示页面已有的会话、当前消息、分数和模型信息。关键词与“私聊 / 群聊明确呼叫 / 公开发言自主参与”筛选覆盖最近恢复的600条有效记录，筛选后最多展示100条。

详情默认按数字顺序展示消息接收、参与判断、回复生成、工具执行和最终发送五个主要节点。请求标识、14项监听、功能耗时、上下文、图片观察和原始资料默认收起，需要时点击展开；旧记录缺少字段时标记未采集。

原生 @ 直接放行不会产生小模型评分。规则层未调用模型时只展示候选和规则原因；不能将未送给模型的流水当作模型依据。模型耗时属于参与判断阶段，不包含碎片等待、爬楼和正文生成。

### 按请求ID排查

1. 在列表复制 `request_id`，粘贴到最近判定搜索框。同一次请求的判定、工具和发送取消沿用此 ID；`session_id` 仍可用于搜索同一会话的多次请求，但只在详情技术明细中显示。
2. 打开“查看详情”，先按1–5核对消息接收、参与判断、回复生成、工具执行和发送结果。需要继续排查时再展开请求标识、监听、功能明细和判定依据。
3. 在主流程或完整事件中查看取消原因和绘图 API 次数。例如工具调用1次、API调用0次，表示工具在预检或额度检查阶段终止；API调用1次、图片投递取消，表示已经请求上游但未发出图片。
4. 进行中的请求点击“刷新追踪”重新读取。前置文字成功不表示最终正文或图片已发送；工具有开始却缺少结束回调时显示未采集结束。

旧记录不补造请求 ID；仅有群号时显示未采集完整 `session_id`，已有完整群聊或私聊 UMO 则原样显示。旧记录的原有判定和耗时仍可查看。

只读诊断接口沿用插件控制台认证：`GET console/request-trace?request_id=<32位小写十六进制ID>` 返回单次追踪，非法ID/不存在/存储不可用分别返回400/404/503；`GET console/listeners` 返回当前实例14项监听注册、最近触发时间、开关和采集健康状态。监听已注册但尚无最近触发时间，表示当前实例尚未观察到该事件。

请求自己的前置文字和分段发送只同步当前请求的上下文版本，真实外部新消息、撤回和过期仍会取消旧回复。修复不会清零或增加生图额度。

## 图片相关设置

| 能力 | 在这里设置的内容 | 生效范围 |
| --- | --- | --- |
| 判定看图 | 视觉模型、缓存、异常兜底 | LivingHello 判定 |
| 独立内容理解 | 图片理解模型 | LivingHello独立模式 |
| 文本排版转图 | 原生 t2i、阈值、模板、渲染方式 | 所选 AstrBot 原生配置 |
| AI生图（文生图 / 图生图） | 模型、协议、尺寸、次数限制 | LivingHello独立能力，全插件共享额度 |

原生配置中已移除图片理解分组，统一使用“内容理解（独立模式）→ 图片理解模型”。

### 配置独立AI生图

1. 展开 **AI生图（文生图 / 图生图）**，选择 AstrBot 已注册模型或多API路由具体上游。
2. 确认所选API支持生图；如同API的生图模型不同，填写“生图模型名称”。留空沿用所选模型名，主对话模型不会因此更换。
3. 选择服务支持的接口和尺寸：标准图片接口对应生成/编辑端点；对话生图接口对应 `image` 模态。
4. 设置每日共享上限，开启AI生图，点击底部保存。默认关闭、每日20次，0禁止生图。

连接复用已配置的API地址和密钥。支持OpenAI兼容图片接口或对话生图接口；原生模型列表中出现的模型未必支持生图，图片理解能力也不等于生图能力。路由候选选择具体上游，生图不会自动切换上游重试。[参数与范围](configuration.md#独立ai生图)。

主模型支持工具调用且需要生图时使用 `livinghello_generate_image`：普通文字要求生成图片；图生图需本次用户输入或引用图片。工具发送图片到当前会话后返回结果供主模型简短说明。原自主回复有效期及取消检查仍生效，生成太慢时可能不发送但仍计用量。超时或结果未知不自动重试。

例如发送“画一只坐在窗边的猫”可使用文生图；附上当前图片并要求“保持主体，把背景改为夜晚”可使用图生图。实际是否调用由主模型决定，应根据工具执行结果核对，不把流程图的计划当成成功结果。

每次上游请求计一次，全插件按服务器自然日共享并持久保存，重载不会清零。密钥继续在宿主或路由中编辑，独立生图不读取 BiliBot 配置。

## 根据记录排查

| 现象 | 优先核对 | 下一步 |
| --- | --- | --- |
| 普通消息不接话 | AstrBot 主动策略、闸门原因、理解状态、预算、超时 | 补真实背景试跑，查看实际 prompt；不要只降阈值 |
| @ 后只回固定短句 | 安静期结束后是否仍是空 @；empty_mention_mode | 空 @ 用 fixed 零模型回应；有问题时传完整批次 |
| 原生模型或分段保存了但会话没变 | 原生编辑目标与会话分配 | 在 AstrBot 检查会话配置，再重新读取 |
| 保存冲突或失败 | 分组结果、版本冲突、宿主保存接口 | 保留草稿，核对最新值后重新读取再保存 |
| 从绫爬楼后没当前答复 | 钩子顺序、准备计时、context_changed / message_expired | 检查配套版本和实际事件；不要自动重发 |
| 人格不一致 | 是否手动选择并保存；配套是否读取固定人格 | 重读目标配置；不存在的人格须手动更换 |
| Token 高于预期 | 小模型是否留空、shadow/legacy、图片兜底次数 | 选定小模型，检查模型实际用量；统计不等于账单 |
| 生图工具没有出现 | 生图是否开启、每日上限是否为0、主模型是否支持工具 | 选好生图API并保存；工具只向符合开关条件的本轮请求提供 |
| 图生图提示缺少图片 | 本次消息或引用是否真正包含图片组件 | 补充图片，勿把模型生成的链接当作参考输入 |
| 生图HTTP失败 | API是否支持所选协议、模型名与尺寸 | 核对服务配置；已请求次数保留，不反复重试 |
| 生图额度减少但图片没发 | 请求是否失败、超时、生成后回复取消或关闭功能 | 查工具结果和每日额度；未知投递先核实，勿自动补发 |

判定记录包含聊天内容；提交问题时只附脱敏后的最小案例，不上传整份用户日志或配置。[维护与恢复步骤](development.md#维护与恢复)。
