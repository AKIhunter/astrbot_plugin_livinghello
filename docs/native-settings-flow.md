# LivingHello 原生配置与流程说明

控制台分为运行概览、判定设置、回复与私聊、流程与试跑四个一级页。

## 原生配置保存

先选择原生配置，再展开模型、人格、图片理解或文本排版转图分组。每个配置标题右侧
的问号解释用途。主对话模型保存到`agent_runner.config.model.provider_id`，
判定小模型仍由判定设置单独选择。回退模型只能选择真实注册的提供者，
不将插件路由的虚拟上游ID写进AstrBot原生配置。

页面底部统一保存，分段、模型/人格、BiliBot文生图、普通参数分别报告保存结果。
存在草稿时锁定目标原生配置，失败保留草稿；刷新使用本地保存的配置选择。
后端共享保存锁，验证字段和读取版本，只合并磁盘白名单字段，保留运行时临时唤醒词、
模型路由及其他配置；原生字段保存后刷新对应流水线。失败恢复触及字段和固定人格。

## 人格固定

手动选择人格或点击“固定当前人格”，再保存才激活。固定选择按原生配置存于
原插件数据目录的`native_persona_pins.json`，不会因页面刷新、文字试跑或旧会话人格改变。
选择“无人格”同样明确固定。以后通过此页面手动更换并保存。

`PersonaManager.resolve_selected_persona`的插件生命周期包装先解析所属原生配置；
固定选择存在时，返回该人格原生对象，让系统提示、开场、工具和技能一致。
没有固定选择时沿用宿主选择器。人格被删除或固定文件损坏时明确失败，不能自动换人。
热重载清理自己的包装，不叠加。新版从绫通过
`get_fixed_native_persona_id(umo)`优先使用同一选择；使用旧版从绫时请同步兼容补丁。

## 图片相关能力

图片转述属于理解；原生`t2i`属于文字排版渲染，两者均按原生配置保存。
AI文生图来自BiliBot已有独立后端，供动态配图使用。此分组修改BiliBot全局公开参数，
影响其所有会话，不自动给普通聊天添加绘图工具。密钥只显示是否配置，必须到原插件编辑。
当前AstrBot与BiliBot没有独立图生图入口，页面禁用该选项，不能把图片理解当成图生图。

## 流程节点

判定：本地规则 → 上下文 → 文字模型 → 按需记忆/视觉 → 视觉异常主模型兜底 →
语义否决 → 阈值 → 结果。每次最多补查一次记忆；正常视觉静默不能触发兜底。
语义否决独立于阈值，互聊、停口、已答、无价值等情况压低分数并禁止放行。

生成：原生模型和固定人格 → 感知复用 → 话题检索 → 证据/记忆回写 → 主模型正文 →
分段 → 时效检查 → 原生发送。只有实际工具结果能证明检索或回写发生。

文字试跑接受消息、上一句及最多30条上下文。消息最多800字，上下文每条最多800字。
使用已保存参数，真实判定会消耗判定模型API用量；不发送消息、不计业务统计和预算，
不读取真实用户记忆、不上传图片、不生成主回复。生成图始终显示计划；
硬闸门否决后显示不会生成。节点可点击或用键盘选中，显示实际尝试、模型、分数、
修正原因、输入数据和已采集耗时。缺失记录显示未执行或未记录，不冒充0耗时。

## 名称兼容

正式名为LivingHello，GitHub仓库为`astrbot_plugin_livinghello`。
技术ID为`astrbot_plugin_LivingHello`（旧名`astrbot_plugin_at_guard`），目录、数据和API已随改名迁移；旧安装按改名脚本搬移即可。
