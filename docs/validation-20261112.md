## 场景覆盖

- 独立 / 仅 Memory / 仅 Emotion / 两者接入：私聊经过实际请求钩子到伪平台发送；不该注入的背景被移除，长期写工具仍保留，共享工具集不被改动。
- 四组合的历史不足路径：无历史时不把情绪当证据，有合法 Memory 结果才补判一次。
- 配套插件缺失降级、Emotion 明确禁聊拦私聊。
- 当前摘要只保存一次、黑名单不保存、私聊旧图工具挂载。
- 普通群消息在途仍判、冷却及关闭入口仍跳过。
- 旧图读取前后变更名单 / 撤回 / 授权，不调用或丢弃结果；有效授权本轮只读一次。

## 44 项既有失败 / 错误的处理

本轮与基准的失败 ID 完全相同，以下是失败证据的分组，**不是已确认的生产根因**。

| 分组 | 当前证据 | 后续排查 |
| --- | --- | --- |
| 配置、UI、旧接口预期不一致 | `gate_congling_prepare_compat`、原生 pin 字段、旧页面文案等缺失 | 逐项核对当前接口，调整过期夹具或修运行逻辑 |
| 配套夹具/依赖缺失 | 从绫夹具 `NameError: policy_for`，Emotion 旧 `reply_freshness_window` 不存在 | 对齐当前配套契约后重测；不得直接宣称线上同样故障 |
| 持久化、故障恢复与通知 | 故障计时、探测、管理员通知断言失败 | 单独用虚拟时钟和真实存储夹具诊断 |
| 上下文、固定人格、响应记录 | 范围复核、重试时间、人格固定、生成/投递标记断言失败 | 对实际运行链路逐项复现，避免只改断言掩盖问题 |

不删除、不跳过这些失败来伪造全绿。本轮部署判据是专项通过且没有新增失败；它不等于修好了上述全部遗留项。

## 验证范围与运行方式

本轮使用合成内容、现有 AstrBot 框架替身、伪 Provider 与伪发送；阻断 IP 网络连接，未调用真实上游，未产生付费模型测试用量，未在生产执行回放。合法性测试替代不了真实模型的语义质量、媒体下载和真人平台投递验收。

仓库基础离线入口：`python3 run_offline_tests.py`。完整 unittest 场景需先安装同入口的 `install_framework_stubs()`，把插件根和 `tests` 加入导入路径，再执行 discover；具体本轮网络阻断执行器随私有执行记录留存。真实联通或语义对照另行安排并先确认费用。
