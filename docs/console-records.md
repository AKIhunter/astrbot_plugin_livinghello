# 控制台记录保留、能力耗时与分页面板

## 页面与保存

`pages/guard/index.html` 使用四个内嵌页：运行概览、判定设置、回复与私聊、最近判定。切换页面只隐藏和显示区域，不重置配置草稿。方向键、Home、End可切页，网址锚点可恢复页签。保存栏全局可用，改回原值不再显示未保存。

调整参与判断、图片与主模型兜底、上下文与记忆时，保存栏额外警示：保存后判定口径变化，旧统计与运行记录仍保留。普通回复节奏修改不显示这项额外警示。后端只验证并保存配置，不触发清零；写入失败恢复运行中配置。独立的“清零统计”操作保留日志，需用户确认。今日计数仍按自然日切换，累计计数保持。

## 日志恢复与搜索

`guard_engine.DecisionLog` 将判定写入 `decisions.jsonl`，超过1MiB轮转至带时间戳的 `decisions.jsonl.archive-*`，不覆盖已有归档。旧版本的 `.1` 继续读取。启动时从多个文件倒序读取并恢复最近600条有效JSON记录，忽略坏行；一次读取64KiB，避免整份大日志读入内存。退出/热重载时强制保存当天统计，避免3秒写盘节流导致计数回退。

`console/state` 默认返回最近100条。`GET console/decisions?query=...` 在已恢复的最近600条中搜索，最多返回100条；归档原文继续留在磁盘。搜索范围在页面明确显示，不承诺查询全部历史。

查询参数从AstrBot的 `request.query` 读取；只在旧宿主缺失该字段时兼容 `args`。上线前使用服务器真实PluginRequest绑定模拟HTTP请求验证群号、私聊QQ、空查询及查询长度限制。

新增记录包含完整会话ID、会话类型、群ID和私聊QQ。旧私聊日志从 `:FriendMessage:` / `:friend:` 的会话标识恢复对象；群记录的发送者不当作私聊对象。详情和列表中的消息按文本输出，避免正文被当成HTML。

## 能力计时

`Decision.timings` 使用版本1结构，每个已调用能力包含 `ms`、`calls`、`status`：

| 能力 | 测量范围 |
| --- | --- |
| text | 所有文字判定调用，包含记忆补查后的文字复判 |
| vision | 多模态判定调用，包含失败与超时 |
| main_fallback | 图片异常后的主模型判定调用 |
| memory | at_guard记忆接口总等待，含身份解析、检索及返回值复核 |
| embedding | 请求向量或等待同请求内共享的向量任务 |
| vector_index | 原生向量索引搜索 |
| memory_read | 记忆文档读取，以及线上权限筛选所需的候选读取 |
| vector_adapter | 旧宿主兼容接口的向量检索总等待，无法拆分时不猜测 |
| retrieval_* | LivingMemory各并发检索分支的总等待 |

模型失败/记忆异常也在finally中记录已花费的时间。不存在的调用不伪报0ms。旧日志可从已采集的模型attempt还原模型耗时，缺失的细分耗时显示“未采集（旧记录）”。新记录未用到的能力显示“未调用”；LivingMemory未提供细分采集器时显示“未采集”。

记忆总耗时包含子步骤，多个分支并发且可能等待同一个共享向量任务，不能把这些数值相加当作总耗时。这里展示的是参与判定阶段，不包含碎片等待、从绫爬楼及主模型正文生成。

LivingMemory的 `core/retrieval/request_timing.py` 通过请求局部ContextVar传递采集器；并发会话隔离，嵌套采集结束后恢复上层采集器。仅记录指标，不记录正文、身份或密钥，不改变查询条件和隐私边界。

## 部署注意

服务器LivingMemory可能带有本地没有的权限筛选补丁。部署计时时应在服务器原文件上加最小计时包装，保留其 `adapter_sql`、`adapter_visible`、FAISS IDSelector及查询过滤逻辑，不直接用本地旧文件覆盖服务器。

本次代码包括此前的碎片续发重置等待、独立私聊等待开关和默认关闭的表达/撤回功能。部署应保留现有配置值，尤其不将用户设置的碎片等待4.5秒覆盖为默认3秒。

部署前离线回归使用模型、消息、记忆和配置替身，不向真实群发送验证消息。实际部署验收还应核对旧日志原文、当天与累计计数、配置保留、插件加载状态和控制台页面。
