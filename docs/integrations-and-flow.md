# 从消息到发送：四种接入组合

对应 LivingHello 2.7.5，源码核对与合成验证日期：2026-11-12。[浏览器流程图](flow/index.html) · [验证报告](validation-20261112.md)。

## 共同主流程

1. **收到消息，检查来源。** 黑名单不读不回；名单外按规则只读背景；灰名单需要明确呼叫。这些限制优先于私聊直接回复、@ 和观察模式。
2. **收集与理解。** 可将同一用户的连续消息合为一批，期限内有效撤回取消整批。转发、引用、卡片和图片有本地解析；配置关闭合并时按单条处理。通知、机器人自己和重复消息不补主动判定。
3. **挂载可用背景。** 有效接入的情绪、关系和记忆随本轮传递；私聊不做参与判定也保留图片摘要与授权旧图工具。只安装插件但开关关闭不会启用背景召回。
4. **决定是否接话。** 默认私聊、正常明确 @、灰名单明确呼叫有直接路径。普通群消息由主动判定范围开关补入口，随后检查冷却、去重、预算、故障状态，文字小模型判断是否理解话题、是否适合参与。需要历史时最多补查并复判一次；需要图片时再看图。正常视觉静默不触发主模型兜底。
5. **生成与工具。** 已允许回复的请求交给 AstrBot 原生主模型与人格。补充事实、写记忆、生图都依赖实际可用工具和模型选择；“计划写入”不等于写入成功。
6. **整理与发送。** 清理思考、正文分段，应用引用、@、语音或转图。每个气泡发送前检查名单、撤回、过期、旧答失效和重复；平台提交成功才记账。已经发送的内容不会因后续取消自动撤回。

`enforce` 表示按判断拦截；`shadow` 表示只记判断仍生成。只有这两种模式，旧值归一到 `enforce`。观察模式不能绕过名单或明确禁聊。

## 接入组合

| 组合 | 参与判定有什么不同 | 回复模型能收到什么 | 长期写入由谁负责 |
| --- | --- | --- | --- |
| 只有 Hello | 流水、上一句、当前文字、图片；缺历史时保持静默，不凭空补记忆 | 原生人格与历史、本轮理解、匹配的短期工具证据 | Hello 没有独立长期库；其它实际写工具可另行提供 |
| Hello + Memory | 按统一身份、会话、人格、受众检索最多 3 条，成功才补判一次 | 已注入记忆可复用，避免重复召回；还可使用可用召回工具 | Memory 原生归档；主模型成功调用长期写入工具 |
| Hello + Emotion | 当轮情绪、关系和可用性参与判断；只有情绪不能证明历史背景已补齐 | 同一事件首份情绪快照；重跑复用，下一轮重新读取 | Emotion 自己维护状态/日记；不替代 Memory 的长期写工具 |
| Hello + 两者 | 历史补证和情绪关系同时参与；补查时关系字段完整保留 | 情绪快照、已有记忆、当轮媒体与工具结果 | 各自维护自己的存储，Hello 不另建副本 |

### LivingMemory

设置位置：AstrBot 管理面板 → 插件 → LivingHello → 配置 → 接入 LivingMemory。开关默认关闭；开启后还需要 Memory 已激活且引擎可用。

Memory 的原消息归档独立运行；前景检索可复用 Hello 已查结果，避免二次召回。主动历史补查必须具有合法统一身份与范围，不能跨人格、受众读到别人的资料。空结果、超时或范围变化不作为有效补证。

**关闭 Hello 接入只关召回。** 清理请求中的 Memory 注入和召回工具，保留 `memorize_long_term_memory` 以及 Memory 自己的原生归档。要停止写入，需到 LivingMemory 自身配置关闭写工具或归档功能；不能把 Hello 开关当作全部停用。

Hello 不会仅因参与判定通过就写记忆。主模型确实拿到写工具、实际调用并成功，才可声称长期写入。短期证据缓存也不是长期库：内存最多 256 条、5 分钟，最多复用 2 条 × 2000 字。

### LivingEmotion

设置位置：AstrBot 管理面板 → 插件 → LivingHello → 配置 → 接入 LivingEmotion。开关默认关闭；生效还取决于 Emotion 已激活、本会话范围和自身模块配置。

Emotion 先注入当轮状态；Hello 冻结本事件第一次状态，再检查可用性。睡眠等 `block_chat` 明确禁聊可阻止默认直接回复的私聊；`available=false` 的主动行为限制只拦主动插话，不自动禁止明确呼叫。能力查询时限为 0.5 秒；插件缺失、接口失联或范围不合法时降级为 Hello 的本地规则，不能视为已读取情绪。

Hello 生成的普通回复和 Emotion 主动行为不是同一条入口。Emotion 自己生成和提交主动行为，发送末端复核租约及 Hello 水位；Hello 的判定日志不能证明主动行为已送达。`host_submission` 只表示宿主接受提交，不等于用户看到了消息。

## 图片与旧答

私聊默认不做参与判定，但 2.7.5 仍把本轮图片摘要保存进原生会话历史。旧图工具仅能读取本轮授权历史引用，近端默认保留 2 个用户轮次 / 4 张图；更旧图片按需补读一次，最长 12 秒、输出上限 1024 token，文字截到 2000 字。它不能让模型任意指定 URL 或文件。

旧图调用前后会复核会话、名单版本、撤回和本轮授权。调用期间撤销授权无法撤销已产生的上游用量，但返回观察不会继续交给回复模型。

默认私聊 15 秒内的新消息可顶替待发旧答；这不等于把两条消息合并，也不保证旧模型任务立即取消。群聊默认不启用水位顶替，设 `watermark_scope=all` 才按窗口执行。代码默认回复有效期为 30 秒，运行者可另设 300 秒；HTML 中默认值不能作为服务器当前值。

## 已知边界

- 转发内部图片未完整接入与顶层附件相同的取图链路。
- 默认私聊跳过参与判定；`[[ASTRBOT_NO_REPLY]]` 响应过滤也受适用路径限制，不能当作所有消息的统一停口开关。
- “不要编造、缺事实就查或追问”是模型要求，没有独立事实审稿保证。
- 配套配套插件只保留经核对的感知与固定人格兼容，动态功能让位于统一耦合。
- 四种组合已在本地框架替身与伪发送下验证；本轮没有调用真实计费模型，也没有给真人发测试消息。
