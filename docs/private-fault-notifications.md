# 功能异常统一私聊

图片理解、语音转写、生图发生真实技术失败时，停止本轮普通回复，异常只通过 QQ 私聊发送给指定管理员。宿主 Agent 的错误消息同样拦截并走管理员私聊，包括由其他用户私聊触发的错误。

接收人优先使用 `outage_notify_admin_qq`，留空则使用 AstrBot 全局管理员中的有效 QQ。提醒受 `classifier_outage_recovery_enabled`、对应 `outage_watch_*` 和既有提醒间隔限制。通知只含纯文本、归一化原因、来源和请求/消息编号，不带原群引用、艾特、异常原文或密钥。

`reply/guard_reply_health.py` 在真实故障上报时同步写入事件标记并停止回复，后台负责留痕和私聊。`input/guard_understanding.py` 将分片来源的故障传回最终请求；`main.py` 在理解、请求契约和发送装饰边界检查标记；`reply/guard_reply_delivery.py` 在逐包发送及打字等待结束时复核，阻止故障发生后继续发送。

阻断不依赖普通回复的引用、艾特开关，也不依赖通知成功。通知关闭、管理员缺失、通知限频或私聊失败时仅留痕，不回退到原群或普通私聊发起人。已发送的气泡不撤回，剩余未发送气泡停止。

预算裁剪、图片张数/调用次数上限、新消息顶替、策略取消、每日生图额度用尽属于既有产品限制，沿用原行为；判定模型失败后成功兜底仍可正常回复。未带故障标记的普通文本不会因为出现“加载失败”等字词被拦截。

离线回归见 `tests/test_private_faults.py`，模型与消息发送均使用替身。本文对应本地代码修改，不代表已部署或真实私聊已实测。
