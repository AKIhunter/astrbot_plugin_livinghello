# 群聊回复、多图处理与异常提醒

本页说明 2026-11-09 的仓库改动，不代表任意部署实例的验收结果。

## 已生成回复的保护

`main.py` 在确认非空且非静默的模型回复后登记生成完成，再检查有效期和上下文。群聊后续插话不会单独撤销已生成的合法答案；生成前仍阻止旧上下文，私聊仍严格检查上下文版本。发送前及分段间持续复核撤回、有效期和消息策略。

LivingEmotion 的配套修改仅在同一群事件同时具有 LivingHello 的策略与新鲜度回调时委托复核；私聊、未接管事件、回调异常仍沿用保守检查，记忆证据授权和配置代次仍独立校验。

## 多图与历史图片

`guard_understanding.py` 将一轮图片分为每批两张、最多两批并发，一轮最多处理12张，合并分片共用最多6次批次调用预算。每批输出上限512 Token；固定路由上游失败时不切换到其他视觉提供者或移除图片后假装成功。输入理解总时限默认20秒；超时保留已完成观察，取消尚未完成批次，明确标注未读或超限图片。

`guard_image_budget.py` 在主请求装配完成后压缩本次内联图片，当前图最多12张、长边1024像素、JPEG质量82，内联总字符预算1 MiB。超限图附省略提示，模型不能猜测未观察画面；缺少 Pillow 或无法解码时按原始大小做预算判断。外部图片引用保留，由宿主读取。

`image_history.py` 只修改请求副本：最近两轮历史最多保留4张原图，更早图片替换为已有逐图观察或明确占位符，原历史对象不变。未提供历史补读工具时应请用户重新引用图片，不能声称已核对细节。

## 异常列表与管理员私聊

`guard_reply_health.py` 根据主模型完成与最终有效消息的发送回执判断回复闭环。工具提示、错误文案、空结果、只有引用或 @ 的消息不算最终正文；部分发送失败或结果未知不自动重发。

异常在 `DecisionLog` 中追加记录，不改写原判定上下文或重复累计判定次数。“最近判断”以异常结果显示同请求记录，同时保留原放行/静默结论、模型原话和评分。正常旁路与取消记录继续各自展示。列表和详情支持以请求编号检索。

群聊宿主错误提示在发送边界被阻止，改为管理员纯文本私聊，附来源群、当前消息摘录、消息编号和请求编号。摘录先隐藏凭据、地址、路径与大段编码，不转发上游异常原文。

配置入口是“回复与私聊 → 断线恢复”。提醒总开关沿用 `classifier_outage_recovery_enabled`，默认关闭；开启后管理员名单为空时使用 AstrBot 全局管理员。`outage_notify_interval_minutes` 默认10分钟，持久化额度在发送前原子认领；热重载、并发异常或未知发送结果不重置额度。提醒关闭或被节流时，每次回复闭环异常仍保留记录。未配置有效管理员或平台不可用时仅留痕。

该机制不是进程外监控。TTS 默认不提醒，只能从宿主已有证据间接观察；进程崩溃、主机离线和未进入受监测流程的外部发送不能凭此确认。

## 官方模型名称

名称后缀只用于区分官方 DeepSeek 的实际思考配置，见[模型选择](configuration.md#模型选择)。Provider ID、请求模型与原生保存值保持不变。删除不存在的旧候选应先核对所有有效配置及运行候选，不能按相似名称删除其他第三方上游。

## 验证与回退

从完整克隆执行 `python3 -B scripts/check_docs.py` 与 `python3 -B run_offline_tests.py`。新测试覆盖群聊生成完成与私聊严格复核、多图并发/超限/部分超时、异常留痕、凭据脱敏、私聊路由和持久化节流，均不调用付费模型或真实消息平台。

从绫交接测试依赖外部源码版本；应使用明确的 `CONGLING_HANDOFF_SOURCE` 并单独报告结果。宿主和配套源码缺失的集成项会跳过，不能据此宣称完成生产联调。

回退以本次提交前的插件源码为基线，重载插件，不恢复运行期间的聊天、记忆或整个数据目录。`reply_health.sqlite3` 是运行状态与提醒额度，不提交仓库，不因回退清零。真实模型语义、平台回执和生产稳定性仍需部署后证据。
