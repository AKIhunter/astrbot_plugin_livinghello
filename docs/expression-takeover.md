# 回复方式与原生分段

AtGuard可独立使用，也可与从绫配套，仅管理回复判定与主回复发送方式。从绫的感知、人设、情绪、关系、记忆、作息和爬楼仍遵循从绫原生配置。

## 回复方式

「回复与私聊 → 回复方式」只有四项：

| 配置 | 作用 |
| --- | --- |
| `expression_takeover_enabled` | 启用回复方式管理，保留旧键兼容；关闭后使用从绫或宿主原生方式 |
| `reply_quote_enabled` | 开启后首条可承载头的正文引用当前有效原消息 |
| `reply_mention_enabled` | 开启后群聊首条正文原生@当前发送者 |
| `expression_strip_emoji` | 清理Emoji/颜文字，保留原字、标点、换行和代码 |

引用与@独立、可同时开启；开启后每次生效，无概率、冷却或次数比例。首条可使用「引用 + @用户 + 正文」，后续段仅正文。无有效消息ID不伪造引用；私聊及不支持的平台不伪造@。工具已有语义引用和正文中对他人的@保留，不重复加头。

表情包由其他插件负责，原生TTS和其他插件生成的图片/语音继续由宿主处理。AtGuard不选择、授权、预约、取消或统计表情包，不合成语音。概率引用、口语字、句末句号移除、换行压平、禁用语、相似回复拦截及私有字数/条数上限均已删除。

## 与AstrBot共用分段

「回复与私聊 → 原生分段回复」直接编辑`platform_settings.segmented_reply`；与AstrBot「扩展功能 → 分段回复」是同一份配置。修改任一处，在另一处重新读取即可查看。

常用参数为启用、正则/词列表模式和发送间隔。高级参数保留原生的仅模型结果、不分段字数阈值、对数底数、清理正则。**超过原生字数阈值时不拆分**，不是按该字数强制硬切。词列表模式遵循宿主去除分段词的行为，正则模式遵循宿主匹配结果。平台限制同样遵循宿主。

迁移保持原生分段当前值，不擅自开启。新引用/@开关首次迁移沿用原生引用/提及开关，已存在新布尔项时保留。只删除已移除的AtGuard配置，等待、理解、撤回、模拟速度、统计、日志和从绫配置不变。

同步接口只接受分段白名单补丁，并检查版本、字段类型、正则、间隔和底数。保存调用原生配置服务及pipeline刷新；不支持的宿主明确报错，不维护另一份私有配置。版本冲突保留页面草稿，重新读取后再保存。失败恢复本次字段，保留其他配置变化。

## 模拟耗时与撤回

模拟耗时仍由`reply_typing_enabled`及`reply_typing_chars_per_second`控制，默认关闭、2.5字/秒。每条实际发送正文等待「非空白字符数÷速度」；25字模拟10秒。原生分段间隔仅执行一次，没有旧AtGuard分条等待。模拟等待不占回复有效期；新消息、撤回和上下文版本仍可取消回复。

群聊/私聊撤回开关独立，不增加处理前等待。收到对应原消息撤回通知，取消未发正文；碎片批次任意原消息撤回会取消剩余回复。已发内容不自动删除。

## 代码逻辑与职责

1. `main.py`登记消息到达、碎片批次与判定版本，保留明确原生@放行。
2. `guard_expression.py`只清理文本与决定引用/@；当前事件启用从绫时，`guard_understanding.py`不追加独立理解。
3. `guard_reply_delivery.py.arm()`只登记结果身份及原语义头，在当前结果的`derive()`上传递发送标记。宿主可创建新Plain、分段、TTS或转图片，无需冻结旧全文。
4. 实际发送包进入事件局部锁，检查撤回/有效期/上下文，每条仅模拟一次。发送成功才消费首条回复头并记录正文；重复组件、部分失败和流式结束不补发全文。
5. 普通非流式回复由原生`ResultDecorateStage`和`RespondStage`唯一拆分、发送。流式保留缓冲后一次最终交付，不增加另一个断句器。
6. `guard_native_reply.py`处理原生配置白名单、摘要版本、保存与恢复；`guard_webui.py`只对外返回分段字段和配置名称。

从绫当前事件是否负责由已激活实例的`enabled_for(event)`决定，重载后重新解析。其感知、记忆、人设和情绪钩子照常执行；AtGuard门禁需要背景时复用本次请求已有原生上下文，不额外查询/重复注入主回复记忆。未启用从绫的事件可独立使用AtGuard理解能力。

## 验证

`python -B run_offline_tests.py`运行离线回归。设置`ASTRBOT_NATIVE_SOURCE`为实际宿主源码根，可运行真实原生装饰/发送方法组合；`CONGLING_HANDOFF_SOURCE`可指定线上候选从绫源码。

测试覆盖回复头四种开关及宿主头组合、原生关/开/阈值/词列表/媒体转换、撤回/过期/上下文变更/重复/部分失败、配置共享/冲突/恢复、从绫原生感知与人设。页面另验390/1280宽度、三页布局、记录搜索/详情与分段草稿。测试不调用真实模型或发送真实消息。
