# 工具前后回复去重

工具调用可能让模型在同一轮中生成多份正文。宿主缓冲合并这些正文时，会把重复内容一起送到装饰与分段流程。本文适用 2.10.1，2026-11-25 核对。

## 生成规则

有可用工具时，LH按模块ID装配一份请求局部规则：需要工具的回答先调用工具，工具返回后再给完整正文；工具调用前和调用之间不写聊天正文。已经说过的句段只补新增内容，失败简短说明，生图继续使用专用的短承接规则。

规则不修改手写提示词或关闭开关，也不写入持久聊天历史；没有可用工具时不添加。没有新增模型调用或重试。

## 合并规则

LH管理的非流式回复在其他装饰插件合并相邻文本前比较工具前后正文。比较时忽略普通聊天标点与空白；段落相同就删除后份，也允许同样原字在不同完整句边界拼接匹配。输出保留第一份原文和后续新增、改写内容，不改写文字。

例如前一份是「设置已确认。」，后一份是「设置已确认。新增功能已开启。」，最终保留「设置已确认。」和「新增功能已开启。」。

前一份「记下了，以后新功能都自动刷新。」，后一份「记下了。以后新功能，都自动刷新。」也只保留首份。后一份如果再有「另有补充。」，该句继续保留；「已确认还有补充。」不会被当成「已确认。」而裁掉前缀。

提前去重只处理正文，不提前分段或清理标点；最终复核继续处理 LE 追加的晚安，随后按配置拆分和清理。因此表情插件先把相邻文本折叠成一个组件也不会掩盖重复来源。

不做相似度整篇裁剪。单份正文内部的有意重复保留；代码、表格、列表、引用、括号、链接、路径、JSON和超出现有字符清理预算的正文保守保留。不跨媒体位置或轮次比较，不改变媒体顺序。没有重复时沿用原拼接方式；流式token始终按原字拼接。

此功能随LH原生分段管理流程执行，不新增配置项。原生宿主自行管理的回复和非模型消息不接入该去重步骤；关闭气泡拆分时，LH管理的正文仍先去重。

## 费用与验证边界

源头规则旨在避免模型再次生成同样内容，但是否遵循由真实模型决定。新增规则为107字符，输入token开销和净费用变化需要实际用量确认。发送前去重不能退还已经生成的token。

`tests/test_reply_merge.py` 用合成样例覆盖新增内容、完整重复、标点与空白变化、完整句边界、多工具步骤、媒体与结构化内容、流式、分段关闭、最大段数、轮次隔离和提示词只装配一份。`tests/test_native_pipeline.py` 验证提前去重、外部文本折叠及追加晚安的顺序。真实宿主函数的回放需要显式提供对应宿主源码；缺少该扩展时该项跳过，其他用例继续。离线通过不代表真实模型已节省费用。
